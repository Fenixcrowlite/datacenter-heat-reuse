# DCHR A36 | Консервативное перераспределение тепла при отключении потребителей

**Дата:** 26.10.2026. **Класс данных:** D_SYNTHETIC (исходный Simulink v08) → D_DERIVED (независимый Python-расчёт). **Статус:** VERIFIED для дискретной модели баланса, **НЕ** валидация физической установки и **НЕ** завершённая Simulink/Stateflow интеграция.

## Исправляемый инженерный пробел

Действующий интерфейс SCADA v09 умеет отключать бассейн и центральное отопление, но отображает исходные показатели ЦОД, теплового насоса, TES и REJECT. При этом освобождённое тепло исчезает из представления what-if. A36 создаёт **изолированную, неуправляющую, покадровую эталонную модель** перераспределения для 672 исходных 15-минутных интервалов здорового синтетического сценария. Производственный сервер, CSV и MATLAB не изменены.

## Балансы и явные допущения

Проверяются исходные равенства в ваттах:

1. `Q_DC_eff = Q_HX + Q_HP_source + Q_reject + Q_leak + Q_unhandled`
2. `Q_HP_pool + Q_HP_DH + Q_HP_charge = Q_HP_source + P_HP`
3. `Q_pool = Q_HX + Q_HP_pool`
4. `Q_DH = Q_HP_DH + Q_TES_discharge`

После изменения лимитов модель сначала оставляет доступный прямой HX в бассейне, затем HP; для ЦО сначала HP, затем TES. При отключении ЦО разряд TES останавливается. Базовая зарядка TES сохраняется. **Переходы температуры бассейна, динамика TES, гидравлика, теплопотери труб и Stateflow-переходы здесь не рассчитываются.** Существующие временные ряды служат только граничными условиями.

Электропотребление компрессора **аппроксимировано** линейным масштабированием `P_HP,new = P_HP,base × Q_condenser,new / Q_condenser,base`. Это постоянный COP для каждого базового интервала, **не** подтверждённая частичная характеристика ТН. Освободившаяся теплота ЦОД направляется в `Q_reject_required`; при заданном условном лимите превышение фиксируется в `Q_unhandled` и помечается **UNSAFE**, а не выдаётся за безопасный теплоотвод. Без подтверждённой мощности REJECT статус остаётся `REJECT_CAPACITY_UNKNOWN`.

## Численные результаты на исходном v08 (168 часов)

Переключение сценариев происходит **после 24-го часа**. Все энергии интегрированы по 672 точкам с шагом 0,25 ч. Единицы: кВт для максимума, кВт·ч для интеграла.

| Сценарий | Макс. необходимый REJECT | Изменение REJECT относительно базы | Изменение прокси энергии компрессора |
|---|---:|---:|---:|
| Исходный | 130,649 кВт | 0 | 0 |
| Бассейн OFF | 138,781 кВт | +5 766,460 кВт·ч | −1 035,091 кВт·ч |
| ЦО OFF | 205,498 кВт | +10 964,239 кВт·ч | −2 816,718 кВт·ч |
| Обе ветви OFF | 213,630 кВт | +16 730,699 кВт·ч | −3 851,809 кВт·ч |
| Лимиты бассейн 40 / ЦО 25 кВт | 186,289 кВт | +10 502,960 кВт·ч | −2 590,797 кВт·ч |

**Не трактовать отрицательное изменение прокси компрессора как экономию электроэнергии всей установки:** вентиляторы REJECT, насосы, потери и реальные кривые COP не пересчитаны. При обеих выключенных ветвях потребность в теплоотводе возрастает до **213,630 кВт**, то есть заметно выше максимального REJECT, наблюдавшегося в исходном синтетическом ряду (**130,649 кВт**). Наблюдаемый максимум не является паспортной мощностью оборудования.

В отдельной **исключительно иллюстративной** чувствительности с REJECT = 150 кВт, обе ветви OFF дают **358 интервалов** превышения (89,5 часа), **2 543,427 кВт·ч** тепла, которое система не смогла бы отвести при таком условном ограничении. Эти интервалы помечены `UNSAFE_UNHANDLED_HEAT`. **150 кВт не подтверждены паспортом или измерением.**

## QA и ограничения

- 17/17 детерминированных unit-тестов PASS, включая отрицательные тесты, сохранение исходных значений при отсутствии изменений и закрытие балансов.
- 4 032 сценарных интервала, **20 833 независимые CSV-проверки PASS** плюс Decimal-проверка прокси COP.
- Контроль SHA256 исходного CSV; исходный файл не изменялся.
- Модель **не** обеспечивает реальный безопасный dispatch, **не** рассчитывает TES SOC, IT-temperature, safety shedding, переменный COP и электрический баланс вентиляторов. Условия разрешения публикации/управления не выполнены.

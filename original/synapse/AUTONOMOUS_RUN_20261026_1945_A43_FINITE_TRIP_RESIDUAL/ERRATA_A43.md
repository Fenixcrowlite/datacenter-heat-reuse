# A43: корректировка идемпотентного воспроизведения регистрации

При первом запуске `register_a43.py` создано **ровно одно** событие evidence №1238 в существующей карточке `scc-3d9d172beb6e1b`. Все 28 файлов исходного SHA-манифеста совпадают с контрольными суммами, SQLite quick_check = ok.

При повторном запуске обнаружена ошибка: текст `FINAL_HANDOFF.md` включал переменное поле `action`. Первый проход записывал `CREATED_EVENT`, повторный формировал `EXISTING_EVENT` и останавливался на `EXISTING_ARTIFACT_CONFLICT`. Повторный запуск **не создавал** второе событие и не менял исходные SHA.

Исправление в собственном scope: `register_a43_v2.py`. При существующем событии он выполняет read-only проверку карточки, receipt, payload, SHA всех 28 файлов, статуса владельца и целостности SQLite, возвращая `EXISTING_EVENT_VERIFIED`. Если события нет, вызывает первоначальную регистрацию. Два последовательных прогона: **0/0 exit**, одинаковый результат `EXISTING_EVENT_VERIFIED 1238 files=28`.

Исходный `register_a43.py`, исходный `FINAL_HANDOFF.md`, исходный SHA-манифест и событие №1238 оставлены неизменными ради сохранения доказательств. Для последующих проверок A43 использовать **только** `register_a43_v2.py`.

Ограничение: эта поправка исправляет идемпотентный повторный вход после уже созданного события. Для будущих задач следует формировать handoff без динамического action-поля, а также добавить регрессионный тест повторной регистрации до финального принятия.

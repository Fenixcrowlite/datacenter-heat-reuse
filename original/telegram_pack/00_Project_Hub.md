## 2. Главные зависимости

- больше **IT-load** -> больше доступного тепла;
- выше **PUE** -> больше общей электроэнергии DC, но не вся она одинаково удобно извлекается;
- выше **температура охлаждающей жидкости** -> меньше температурный подъём теплового насоса -> выше COP;
- ниже требуемая **температура теплосети** -> выше COP;
- холоднее на улице -> выше тепловая нагрузка зданий;
- накопитель не создаёт энергию, он переносит её во времени;
- высокая электрическая цена или углеродоёмкость сети может съесть экономический/CO2 эффект теплового насоса;
- слишком большая мощность DC при маленьком спросе означает curtailment, то есть часть потенциального тепла некуда деть.

## 3. Что смотреть в результатах

`results/scenario_summary.csv` — итог по сценариям.

Ключевые KPI:
- `Coverage` — доля спроса теплосети, закрытая DC + storage;
- `MeanCOP` — средневзвешенный COP;
- `ERF` — Energy Reuse Factor;
- `ERE` — Energy Reuse Effectiveness;
- `GasHeat_MWh` — сколько тепла всё ещё надо дать газом;
- `CurtailedHPHeat_MWh` — сколько потенциального тепла не использовано;
- `OpexSaving_EUR`, `CO2Saving_t` — относительный эффект против газового baseline при заданных предположениях.

## 4. Код

- `matlab/default_config.m` — единственная точка базовых параметров.
- `matlab/+dchr/make_inputs.m` — погода и IT-load.
- `matlab/+dchr/heat_demand.m` — спрос тепла.
- `matlab/+dchr/heat_pump_capability.m` — COP и мощность HP.
- `matlab/+dchr/simulate_system.m` — диспетчеризация системы.
- `matlab/+dchr/compute_metrics.m` — KPI.
- `matlab/run_experiment.m` — сценарный эксперимент.

## 5. Правило исследования

В документации параметры помечаются как:
- **LITERATURE** — взято из публикации/официального источника;
- **SCENARIO** — выбранное нами число для эксперимента;
- **CALIBRATE** — параметр, который позже надо определить по реальному объекту;
- **DERIVED** — вычисляется из модели.

Так мы не будем заниматься древним человеческим ремеслом превращения красивого числа из воздуха в «данные исследования».

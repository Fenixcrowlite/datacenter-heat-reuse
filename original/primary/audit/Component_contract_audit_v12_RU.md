# Аудит компонентной модели v0.12

Проверка: `python audit/test_component_contract_v12.py`. Результат: **12/12 PASS**, в том числе один агрегированный property-тест на 3000 воспроизводимых сценариях (seed 12026). Машинный отчёт: `audit/component_contract_reference_tests_v12.json` с SHA-256 исходников.

Проверены тождества первого закона для теплового насоса, ограничение источника, покрытие спроса, энергетический баланс TES, пределы SOC, ограничение резервного котла и отказы на невалидных входах. Погрешность 1e-8. Это проверка независимого Python reference, а НЕ проверка оригиналов публикаций и НЕ независимая экспериментальная валидация.

**F12-01 HIGH:** `matlab/+dchr/simulate_system_v2.m` содержит `qGas(k)=max(0,qNeed-qDirect-qDis(k));` без ограничения мощности котла и расчёта непокрытого спроса. При высоком спросе модель может искусственно закрыть весь дефицит газом. Нужны конечная мощность и отдельный `Unmet_Heat_MW`.

**F12-02 MEDIUM:** `matlab/+dchr/+components/storage_step.m` не валидирует положительность dt, диапазон эффективностей и допустимый SOC. При невалидных входах возможны некорректные численные результаты. Подтверждено статическим чтением, динамически в MATLAB не проверено.

**F12-03 MEDIUM:** `matlab/+dchr/+components/heat_pump.m` молча заменяет нулевой/отрицательный температурный подъём на 1 K. Требуется отдельная логика режима прямого теплообмена и физическая область применимости HP.

Создан `matlab/run_component_contract_v12.m` для runtime-проверок, но запуск MATLAB batch заблокирован инструментом. Старые версии не менялись. Следующий этап: исправление в новых v13-файлах, затем запуск MATLAB и сопоставление с Python reference.

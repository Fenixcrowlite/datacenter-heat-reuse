# DC SCADA v09 — проверка и приёмка

**Область: LOCAL SIMULATION ONLY / D_SYNTHETIC / качество D.** Проверки аппаратного управления не проводятся: таких функций нет. Исходные CSV/QA читаются без изменений, модели MATLAB/Stateflow не запускаются. Docker, FUXA и постоянные службы при реализации не стартуют.

## Автоматическая проверка

Из корня проекта:

```powershell
C:\Python314\python.exe -m unittest discover -s tests -v
C:\Python314\python.exe -m compileall -q .
node --check .\web\app.js
```

Тесты поднимают только временный локальный HTTP-сервер внутри процесса тестирования, завершают его и используют временные runtime-папки внутри `scada_v09`. Они не удаляют операторский `STOP` в корне и не обращаются к Docker, MQTT или промышленным устройствам. Фактический результат выполнения фиксируется отдельно в `CODEX_RESULT.md`.

## Ручная приёмка HMI — после явного запуска инженером

1. Если корневой `STOP` присутствует, сначала убедиться, что `start_scada.ps1` отказывает и не удаляет его. Не удалять STOP в целях теста без решения инженера.
2. Запустить HMI вручную. Проверить фактический loopback адрес, начальное pause, заметную маркировку SIMULATION/SYNTHETIC D и отключённый REAL CONTROL / PLC.
3. Сверить snapshot строки 0 сценария `zdravy`: `cas_h=0`, `Q_DC_eff_W=200000`, `Q_pool_phys_W=150000`, `T_pool_C=16.068635804129`. Значения округляются только в отображении; API хранит исходную числовую точность.
4. Проверить мнемосхему: направления и подписи потоков читаемы; REJECT A и B разделены; DC/HP/бассейн/TES/DH имеют инженерные имена. Числа и активность линий должны следовать текущему CSV, нулевой поток не изображается активным.
5. На 1920×1080 и планшете примерно 1024×768 проверить кириллицу, контраст, отсутствие перекрытия элементов, доступность кнопок/подписей и горизонтальную прокрутку только там, где нужна схема/таблица.
6. На двух трендах проверить ось модельного времени, легенду и переключение серии, hover/курсор и масштаб/окно. Значение под курсором должно соответствовать дискретной исходной строке. Ряды мощности не получают фиктивные промежуточные отсчёты.
7. Проверить play/pause, скорости 0,5 и 16, seek и смену сценария. На конце ряда должно наступить pause. Сравнение другого сценария не должно менять текущий replay и не должно маркировать будущие исходные точки как уже посещённую историю.
8. Сценарии отказов: сверить тревоги с флагами CSV, увидеть CRITICAL и WARNING, квитировать одну тревогу. Убедиться, что safety_latch исходной строки остаётся прежним.
9. Убедиться, что `T_IT_model_C` подписан как модельный риск, не CPU. SOC TES — «н/д», энергия TES доступна в кВт·ч; COP берётся из `COP` CSV.
10. Во время play выполнить `stop_scada.ps1`. STOP должен сохраниться, owned process завершиться корректно при доступном HTTP. При отказе HTTP не должно быть forced kill. После остановки повторный start должен отказать до явного решения оператора о STOP.

## Негативные и эксплуатационные проверки — только локально

- Второй экземпляр: сервер должен отказать из-за OS lock/занятого порта; пользовательские процессы не завершаются.
- Занятый 8091 без своей SCADA: только default запуск переходит на 8092 с понятным логом; явный `--port 8091` должен отказать. Оба заняты — отказ.
- Просмотр Browser Network: никаких внешних шрифтов, библиотек, CORS или запросов в интернет.
- После нескольких повторов одной записи число SQLite samples для пары source/scenario/index не увеличивается. Alarm events ≤5 000, log rotation работает.
- `/api/control` без token, с неверным token, чужим Origin, отрицательными/нечисловыми аргументами, лишними ключами и путями не должен менять данные вне разрешённого clamp.
- Отключение/включение replay не должно создавать сокеты к PLC и не должно менять исходные CSV/QA или MATLAB файлы.

## Отложенная приёмка MQTT/Docker/FUXA

Эти шаги выполняются только если инженер отдельно решит запускать Docker и установит paho-mqtt. Они **не считаются выполненными** при сдаче native HMI.

1. При остановленном Docker bootstrap отказывает, не запускает Docker Desktop. При наличии `.env/passwords` не перезаписывает секреты.
2. При ручном bootstrap пароли не видны в выводе/аргументах Docker; `.env` и `docker/runtime/` игнорируются Git и ограничены ACL текущего пользователя.
3. `docker compose --profile fuxa config` и явный запуск профиля: host ports только `127.0.0.1`; RAM в пределах лимитов; FUXA/Grafana не запускаются без профиля.
4. Mosquitto отклоняет anonymous, viewer не может публиковать, exporter не может подписываться. Обе роли не имеют доступа к темам вне `dchr/v09/sim/#`.
5. Bridge получает локальный snapshot, публикует только D и numeric tags. HTTP redirect, внешние адреса, non-D и аппаратный источник отклоняются. Ключ csrf_token ни в одной MQTT теме не появляется.
6. Остановка bridge/STOP или потеря связи делает `bridge_state=offline` через orderly shutdown/Last Will. FUXA проверяет свежесть `exported_at_unix`; retained не трактуется как живой датчик.
7. FUXA подключается к `broker:1883` как `fuxa_viewer`; числовые поля извлекаются из JSON `value`, корректные единицы W/°C/J, без PLC-устройств и кнопок команд.
8. Запустить отдельный профиль Grafana только при необходимости. Проверить вход с локальным secret и отключённый anonymous; источники данных настраиваются отдельно.

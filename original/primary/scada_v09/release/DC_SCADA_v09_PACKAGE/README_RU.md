# DC SCADA v09 — локальный симуляционный HMI

**LOCAL SIMULATION ONLY · D_SYNTHETIC · качество D. Управление реальным оборудованием/PLC отключено.** Интерфейс показывает воспроизведение исходных CSV Simulink v08; это не эксплуатационная SCADA и не телеметрия физических датчиков. Изменение скорости, сценария, позиции и квитирование влияют только на локальную симуляцию.

Бассейн проекта: **500 м³**. UI на русском языке сохраняет инженерные словацкие теги. Ядру достаточно Python 3.14 и браузера: сторонние пакеты, Docker, интернет и внешние шрифты не нужны.

## Быстрый запуск

Откройте PowerShell в этой папке и выполните вручную:

```powershell
.\start_scada.ps1
```

Скрипт запускает только `scada_server.py`, скрывает отдельное окно процесса и проверяет готовность по PID и `instance_id`. По умолчанию адрес — `http://127.0.0.1:8091/`. Если занят только порт 8091, сервер явно сообщает о переходе на 8092. Скрипт выводит фактический адрес. Другая конфигурация запуска:

```powershell
.\start_scada.ps1 -Port 8093
# Или видимый процесс в текущем терминале, завершаемый Ctrl+C:
C:\Python314\python.exe .\scada_server.py --port 8093
```

Скрипты не меняют firewall, питание Windows, автозагрузку и пользовательские службы. Повторный запуск блокируется проверкой собственного процесса и эксклюзивной привязкой порта.

## STOP и завершение

```powershell
.\stop_scada.ps1
```

Скрипт создаёт и сохраняет файл `STOP`, проверяет принадлежность PID и HTTP `instance_id`, затем запрашивает корректное завершение своего сервера. Принудительное завершение процессов не применяется. Если HTTP недоступен, `STOP` всё равно остаётся: работающий сервер должен остановить воспроизведение и показать тревогу. Мост MQTT тоже завершает работу при `STOP`.

Ни один скрипт автоматически не удаляет `STOP`. При наличии `STOP` запуск через скрипт запрещён; сервер, запущенный напрямую, остаётся в остановленном состоянии, а команды запуска/сброса/перемотки/смены сценария заблокированы. Чтобы вновь разрешить **симуляцию**, инженер должен самостоятельно проверить причину остановки, явно удалить именно локальный файл `scada_v09/STOP` и запустить приложение. Аппаратное управление от этого не включается.

## Данные и честная интерпретация

Приложение читает только заданный каталог `../results/pool_measurement_v08/`: восемь `sim_v08_*_SK.csv`, по **672 строки**, шаг **900 с**. Значения `cas_h` идут от `0` до `167.75`: это 672 интервала четверти часа и заявленное покрытие 168 ч; последняя сохранённая отметка — 167 ч 45 мин. CSV остаются неизменными; отсутствующие значения не заменяются вымышленными, интерполяция не применяется.

Файл `QA_NEZAVISLA_V08_SK.json` содержит `PASS`, 91 565 проверок и собственную классификацию `D_SYNTHETIC_REPLAY`; каждый сценарий помечен `D_SYNTHETIC`. Это проверка соединений/арифметики модели, **не калибровка по измерениям и не подтверждение независимости полевых датчиков**. HTTP/UI всегда сохраняют класс D синтетического происхождения.

Важные ограничения показателей:

- `T_IT_model_C` — **индикатор теплового риска модели IT**, не фактическая температура CPU.
- `Q_DC_eff_W` — эффективная тепловая мощность DC в конкретной строке; `Q_DC_source_raw_W` — отдельная исходная величина. Их нельзя подменять друг другом.
- `COP` берётся из CSV. `P_HP_W` — электрическая мощность теплового насоса; `Q_pool_phys_W` — физическая тепловая мощность в бассейн, а не команда.
- `E_TES_J / 3 600 000` даёт запас энергии TES в кВт·ч. **Ёмкость TES по одним CSV не установлена:** процент SOC должен оставаться «н/д». Максимум наблюдавшегося ряда не считается паспортной ёмкостью.
- `Q_reject_main_W`, `Q_reject_backup_W`, `Q_unhandled_W` и диагностические флаги — исходные величины модели. Тревоги HMI не заменяют промышленную систему защиты.

## Работа в HMI

Выберите сценарий, нажмите воспроизведение, задайте скорость **0,5…16 исходных отсчётов/с**. Скорость — число строк CSV в секунду реального времени; при 1 отсчёте/с проходят 15 модельных минут за секунду. Ползунок меняет позицию дискретно, без синтеза промежуточных измерений. Конец сценария приостанавливает воспроизведение.

На мнемосхеме видны DC, výmenník tepla, tepelné čerpadlo, bazén, TES, CZT/DH и REJECT A/B. Анимация линий — визуальное представление потока из CSV, а не моделирование трубопроводной гидравлики. Тренды используют исходные временные отметки; сравнение сценариев показывает сохранённые серии. Квитирование только отмечает локальную тревогу и не сбрасывает `safety_latch` исходной модели.

История и локальные квитирования хранятся в `runtime/history.sqlite`. Записи привязаны к сценарию и исходному отсчёту; повторное воспроизведение не должно дублировать строки истории. Логи ограничены ротацией. `runtime/`, `STOP` и локальные секреты исключены через `.gitignore`.

## API

Чтение: `GET /api/health`, `/api/status`, `/api/scenarios`, `/api/snapshot`, `/api/history?limit=...`, `/api/historian?limit=...`, `/api/alarms?limit=...`. `/api/history` возвращает точные исходные отсчёты для тренда, а `/api/historian` — фактически посещённые отсчёты SQLite. Для полного сравнения исходного сценария допускается `/api/history?scenario=zdravy&scope=full&limit=672`; эти данные не выдаются за историю посещений. `GET /healthz` — проверка доступности. HTML отдаётся по `/`. Состояние обновляется UI опросом примерно раз в секунду; это локальные данные воспроизведения качества D.

Команды: `POST /api/control` с JSON и заголовком `X-SCADA-Token`, полученным из локального `/api/status`. При наличии `Origin` он должен совпадать с текущим локальным origin сервера. Чужие origins, произвольные пути, неизвестные команды и некорректные значения отклоняются. CORS, PLC endpoints, внешние записи и запуск произвольных программ не предусмотрены. Не публикуйте токен из `/api/status`.

## Необязательные MQTT/FUXA/Mosquitto

**Эта часть отложена и не нужна для HMI. Docker автоматически не запускается.** Требуется отдельно установленный `paho-mqtt` только для `mqtt_bridge.py`. Мост читает исключительно локальный HTTP snapshot, публикует `dchr/v09/sim/...`, сохраняет `D_SYNTHETIC`, качество D и запрещённое аппаратное управление; подписок и каналов команд нет. Разрешены только loopback API и loopback MQTT broker. Перенаправления HTTP и системные proxy не используются.

Если инженер явно решит использовать дополнительную память Docker, он самостоятельно запускает Docker Desktop, затем:

```powershell
.\docker\bootstrap.ps1
docker compose --profile fuxa up -d
# Отдельное foreground-окно, только после установки paho-mqtt:
.\docker\start_mqtt_bridge.ps1
```

Bootstrap выполняет один временный контейнер `mosquitto_passwd`, создаёт случайные отдельные учётные данные экспортёра и FUXA, сохраняет `.env` и `docker/runtime/passwords`, ограничивает Windows ACL и не выводит пароли. Существующие секреты не перезаписываются. `.env` и `docker/runtime/` игнорируются Git. В bootstrap не выполняются запуск Docker Desktop или запуск постоянных контейнеров. Образы могут потребовать первоначальной загрузки; перед использованием в постоянной среде зафиксируйте проверенные digest/version.

В FUXA (`http://127.0.0.1:1881/`) вручную создайте MQTT connection к `broker:1883`, используя `FUXA_MQTT_USERNAME`/`FUXA_MQTT_PASSWORD` из локального `.env`. Это отдельная учётная запись **только чтения**; credentials экспортёра в FUXA не применять. Включите локальную авторизацию самой FUXA перед дальнейшим использованием. PLC/Modbus/S7 устройства, команды и кнопки записи не добавляйте.

| Тег FUXA | MQTT topic | JSON поле | Единица / смысл |
|---|---|---|---|
| T_pool_C | `dchr/v09/sim/tag/T_pool_C` | `value` | °C, модель бассейна |
| Q_DC_eff_W | `dchr/v09/sim/tag/Q_DC_eff_W` | `value` | W, эффективное тепло DC |
| Q_pool_phys_W | `dchr/v09/sim/tag/Q_pool_phys_W` | `value` | W, тепло в бассейн |
| P_HP_W | `dchr/v09/sim/tag/P_HP_W` | `value` | W, электричество HP |
| COP | `dchr/v09/sim/tag/COP` | `value` | безразмерный COP из CSV |
| T_IT_model_C | `dchr/v09/sim/tag/T_IT_model_C` | `value` | °C, риск модели, не CPU |
| E_TES_J | `dchr/v09/sim/tag/E_TES_J` | `value` | J, без выдуманного SOC |
| Q_DH_W | `dchr/v09/sim/tag/Q_DH_W` | `value` | W, CZT / district heat |
| Q_reject_main_W | `dchr/v09/sim/tag/Q_reject_main_W` | `value` | W, REJECT A |
| Q_reject_backup_W | `dchr/v09/sim/tag/Q_reject_backup_W` | `value` | W, REJECT B |
| Q_unhandled_W | `dchr/v09/sim/tag/Q_unhandled_W` | `value` | W, необработанное тепло |
| safety_latch | `dchr/v09/sim/tag/safety_latch` | `value` | исходный флаг модели |
| Состояние моста | `dchr/v09/sim/bridge_state` | `state` | online / offline |

Все числовые поля CSV публикуются таким же способом; полный объект — `dchr/v09/sim/snapshot`. Каждый payload содержит качество D, scenario/index и время экспорта. Поддержка извлечения JSON у конкретной версии FUXA настраивается вручную и здесь не проверена. **Retained MQTT данные могут устаревать:** проверяйте `exported_at_unix` и `bridge_state`, не интерпретируйте retained как живое измерение. При переходе сервера на 8092 исправьте только локальный `SCADA_URL` в `.env`.

Mosquitto: `127.0.0.1:18883`, anonymous запрещён, ACL разрешает экспортёру только запись simulation topics, FUXA только чтение. FUXA ограничена 512 МБ, broker — 128 МБ. `restart: no`, host networking и privileged отсутствуют. Grafana — отдельный профиль `grafana`, лимит 256 МБ, первоначальный пароль в `docker/runtime/grafana_admin_password`; источники данных/дашборды не настроены. Для остановки optional stack используйте `docker compose --profile fuxa --profile grafana down`; без `-v` постоянные тома сохраняются.

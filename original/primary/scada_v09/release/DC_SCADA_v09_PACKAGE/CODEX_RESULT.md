# Результат реализации DC SCADA v09

Создан функциональный локальный HMI для воспроизведения **D_SYNTHETIC / качество D**. Ядро использует только Python 3.14 stdlib; интерфейс — HTML/CSS/JavaScript без внешних библиотек, шрифтов и сетевых загрузок.

## Файлы и возможности

- `scada_server.py` — сервер только `127.0.0.1`, порт 8091 с явным fallback на 8092 при занятости; OS lock от дублей; CSRF/Origin/Host защита; ограниченные команды replay; polling API; SQLite historian и квитирование; ротация логов.
- `web/index.html`, `web/styles.css`, `web/app.js` — русский тёмный HMI со словацкими техническими именами, SVG-мнемосхемой, KPI, двумя основными интерактивными ступенчатыми трендами и графиком сравнения, тревогами, посещённой историей SQLite и экспортом CSV.
- `start_scada.ps1`, `stop_scada.ps1` — ручной запуск с проверкой идентичности процесса и корректное завершение только своего сервера. STOP сохраняется; принудительное завершение чужих процессов отсутствует.
- `mqtt_bridge.py` — необязательный экспорт только симуляционных данных в MQTT, без подписок и команд; loopback, качество D, ограниченная очередь, защита от публикации CSRF-токена.
- `docker-compose.yml`, `docker/mosquitto.conf`, `docker/acl`, `docker/bootstrap.ps1`, `docker/start_mqtt_bridge.ps1` — отложенный защищённый стек Mosquitto/FUXA; Grafana отдельным профилем; случайные секреты только в игнорируемых локальных файлах.
- `README_RU.md`, `ARCHITECTURE_SK.md`, `TEST_PLAN.md`, `.gitignore`, `tests/test_server.py` — запуск, архитектура, границы достоверности и проверки.

## Проверенные исходные данные

Прочитаны реальные восемь `sim_v08_*_SK.csv` из `../results/pool_measurement_v08/`: **8 × 672 = 5376 строк, 73 столбца, шаг 900 с**, отметки `cas_h=0…167.75`, номинальное покрытие 168 ч. Все числовые значения сравниваются тестами с CSV без интерполяции. SHA-256 каждого CSV доступен в API/UI.

QA `PASS`, 91 565 проверок, исходная классификация QA `D_SYNTHETIC_REPLAY`. Это проверка связей модели, не калибровка и не подтверждение независимости полевых датчиков. `COP` взят непосредственно из CSV. Подтверждённая ёмкость TES в предоставленных данных не найдена: энергия показывается в кВт·ч, SOC остаётся неизвестным. `T_IT_model_C` явно подписан как модельный риск, не фактическая температура CPU.

HTTP-тесты использовали временные loopback listeners и временные SQLite внутри этой папки; после тестов они закрыты. В рамках реализации постоянный сервер не запускался.

## Ограничения и приёмка

Docker Desktop, контейнеры и bootstrap **не запускались**. FUXA не настроена через UI, MQTT/broker и Grafana сквозным запуском не проверялись. Внешний пакет paho-mqtt нужен только для явно запускаемого optional bridge. Версии Docker-образов следует зафиксировать после отдельной приёмки.

При финальной проверке в `runtime/` обнаружены артефакты отдельного QA-запуска, включая `QA_HMI_1600x940.png`. Этот готовый скриншот просмотрен: верхняя панель, KPI и видимая часть мнемосхемы читаемы и заполнены исходными значениями. Созданные другим запуском процессы и runtime-данные не изменялись.

Полная интерактивная приёмка в настоящем браузере на 1080p/планшете и запуск пользовательских PowerShell-сценариев остаются по `TEST_PLAN.md`. Проверки JavaScript и просмотр одного скриншота не заменяют такую приёмку.

Исходные MATLAB/Stateflow, CSV/QA, пользовательские службы, конфигурация системы, firewall и питание не изменялись. Все созданные файлы находятся в `scada_v09`. STOP не удалялся. Аппаратные действия всегда отключены: **это симуляционные артефакты**.

Ручной запуск после проверки STOP: `./start_scada.ps1`. Подробности — `README_RU.md`.

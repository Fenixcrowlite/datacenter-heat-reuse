# SCADA каскад v03 — синхронизация главной мнемосхемы (23.10.2026)

## Исправленный дефект

При выключении бассейна/центральной теплосети в каскаде v02 главный SVG продолжал показывать исходные данные Simulink v08 (например бассейн 27,6 °C, 9,7 кВт), потому что обработчик `renderSnapshot` перерисовывал его из серверного replay. Получалась несогласованная визуализация.

## Результат: VERIFIED браузерными испытаниями

- Для изменённого каскада SVG и KPI главной панели отражают выбранный сценарий и **тот же выбранный момент времени**. Подпись `КАСКАД v02 · WHAT-IF / D_DERIVED` перечисляет режимы и источник.
- Бассейн OFF: температура воды продолжает меняться по теплоёмкости и потерям; теплоподача **0 кВт**, знак **БАССЕЙН OFF**, потоки HX→бассейн и HP→бассейн визуально погашены. Для проверенного отсчёта #321: **18,4 °C**, **0,0 кВт**.
- ЦО OFF: теплоподача **0 кВт**, знак **OFF**, поток в ЦО погашен; бассейн остаётся в выбранном режиме.
- Догрев ТН OFF: убран только вклад `Q_HP_pool`, прямой HX остаётся.
- Совместное OFF и ограничители мощности работают как ранее. После возврата в базовый пресет исходная серверная мнемосхема восстанавливается.
- Главный интерфейс обновляется сервером раз в секунду; новый слой сохраняется после каждого `renderSnapshot`.
- При клике на бассейн/ЦО/HX карточка значений показывает расчётные значения и исходные reference v08 отдельно.

## Важное разграничение

Это **сценарная UI-визуализация D_DERIVED**, а не физический выход оборудования. Все базовые данные DC, HP, TES, REJECT, IT маркируются звездочкой и происходят из исходного CSV выбранного сценария/отсчёта. Эти потоки не перераспределены: новая схема НЕ означает полный новый согласованный прогон Stateflow. Тренды, тревоги и historian далее по странице по-прежнему отражают отдельный серверный native replay; экран об этом предупреждает.
